ORCA

An architectural pattern
Operational store, Read models, Change capture, Anti-corruption layer. A pattern for building a fast, independent platform on top of a system you do not own and cannot change.
Many organizations run their core business on a vendor’s system: a database you can read, but whose schema, release cycle and API belong to someone else. Everything else grows around it. Tools query it directly, each keeps its own drifting copy, the vendor’s quirks leak into every one of them, and the API is too slow and too incomplete to build on.
The usual answers do not fit. Building on the vendor’s API lacks the reads you need. Turning on the database’s change tracking alters a schema you do not own. Mirroring the database gives you speed, but every app still speaks the vendor’s model. ORCA is the shape that remains: own a translated, live copy for reads, and send every write back through the vendor.
Change capture
A signal of which records changed, taken from outside the vendor’s schema. A hint, never a fact.
Operational store
Your own copy. Every hint is re-read from the source, committed only, and reconciliation always wins.
Anti-corruption layer
One library that turns the vendor’s model into yours, so nothing else ever sees it.
Read models
Screen-shaped documents, versioned in commit order and delivered only as whole versions.
Writes
Through the vendor’s API, judged by what comes back: confirmed, state reached, or undetermined.

Dokkit

Monitoring
One place that watches everything I run and tells me what needs my attention.
The first screen is what needs a look now, which is wider than what is down. The program on each machine opens no port and reports what is on it. Discovery writes a proposal, and nothing is watched until a person accepts it. It suggests changes to its own rules and never makes them.

steddi

iOS navigation
For people who already know their routes. Rerouted only when it actually matters.
Drive a route your way once and it is saved. Turn-by-turn is its own engine, with no navigation SDK. A faster way is offered only when it saves enough of what is left of the drive: a larger share on a short drive, a smaller one on a long drive, never less than a minute and a half, and never in the last three minutes.

coil

Python compiler
Directory in, executable out.
Existing tools for turning Python into an executable are complicated: hidden imports, missing DLLs, spec files, hook scripts. Coil takes a project folder and returns an .exe with no configuration. The executable is a native launcher, not a renamed interpreter, so the arguments you pass are the arguments your program gets.
